# 投标制作交互重构设计 · 标段工作台

- **日期**: 2026-06-29
- **状态**: 设计已确认，待生成实施计划
- **目标用户**: 业务人员（投标专员/销售）优先，傻瓜式流程
- **改造范围**: 前端 + 后端

## 1. 背景与问题

当前投标制作流程入口分散、心智模型割裂，业务人员找不到入口、不知道下一步去哪。具体痛点：

1. **入口找不到**：「标书制作」是一级菜单，但点进去是空页面（`OutlineListView` 无 `lot_id` 时显示"请从项目详情进入大纲管理"）。用户必须走 项目详情 → 标段 tab → 大纲按钮 才能进入，路径无人指引。
2. **流程割裂**：上传文件在「项目详情→文件 tab」，AI 生成大纲要选招标文件却在「大纲列表→新建大纲→AI 解析」弹窗里，两处分离，用户上传完不知道下一步去哪。
3. **标段概念重**：标段是隐式中枢（文件要关联标段、大纲从标段进入、工作流挂在标段上），但标段只是项目详情里的一个 tab，用户心智里没有这层，常被"请先关联标段"卡住。
4. **状态不透明**：上传/解析/生成是异步任务，靠前端 `setInterval` 轮询单个资源，离开页面就看不到进度。

## 2. 方案选型

采用 **方案 A：标段工作台 + 步骤导航**。

- 标段升级为独立工作台路由 `/projects/:id/lots/:lotId`
- 顶部步骤导航条（5 步），左侧常驻文件&大纲列表，主区随步骤切换
- 后端新增聚合状态接口，解决跨页面/刷新后状态可见性
- 业务人员沿主线走，老用户可跳步；投标迭代非线性，故不采用向导式

## 3. 信息架构与导航

### 路由结构

```
/projects                          项目列表
/projects/:id                      项目详情（瘦身：概览/成员/标段列表）
/projects/:id/lots/:lotId          标段工作台 ★ 新增主战场
/outlines/:outlineId               大纲详情（保留，从工作台跳入）
/tender/files/:fileId              文件详情（保留，从工作台跳入）
```

### 菜单调整

| 菜单项 | 改动 |
|--------|------|
| 工作台 | 不变 |
| 项目管理 | 不变（入口） |
| ~~标书制作~~ | **移除**——当前是空页面，制造困惑 |
| 流程模板 | 不变 |
| 知识库管理 | 不变 |

**理由**：标书制作不是独立功能，是某个标段的制作过程。移除后心智模型变为 **项目 → 标段 → 工作台**，一条线无断点。

### 项目详情页瘦身

保留 3 个 tab：
- **概览**：项目信息 + 标段进度看板（见 §7）
- **成员**：项目管理员用
- **标段**：标段列表，点标段 → 跳 `/projects/:id/lots/:lotId`

原"文件"tab **移除**——文件操作挪到标段工作台（文件本就关联标段，现在上传弹窗里也要选标段，说明文件属于标段上下文）。

## 4. 标段工作台布局

路径 `/projects/:id/lots/:lotId`，重构核心页面。

### 页面结构

```
┌─────────────────────────────────────────────────────────┐
│ 顶部：面包屑 + 标段标题 + 标段状态徽章                       │
├─────────────────────────────────────────────────────────┤
│ 步骤导航条（5 步，可点击跳转）                              │
│ ① 招标文件 ──② 文件解析 ──③ 大纲生成 ──④ 内容编辑 ──⑤ 导出 │
├──────────────┬──────────────────────────────────────────┤
│ 左侧：文件&大纲  │ 右侧：主工作区（随步骤切换）              │
│                │                                          │
│ 📄 招标文件      │  [当前步骤的内容]                          │
│  · xxx.docx ✓  │                                          │
│  · yyy.docx 解析中│                                        │
│                │                                          │
│ 📝 大纲         │                                          │
│  · 主大纲 v1 ✓  │                                          │
│  · 草稿 v2     │                                          │
│                │                                          │
│ [+ 上传文件]    │                                          │
│ [+ 新建大纲]    │                                          │
└──────────────┴──────────────────────────────────────────┘
```

### 五个步骤

| 步骤 | 主工作区显示 | 触发动作 |
|------|-------------|---------|
| ① 招标文件 | 拖拽上传区 + 文件列表 | 拖拽即传，lot_id 自动填充 |
| ② 文件解析 | 解析进度 + 结果摘要 | 自动解析（后端已有），失败可重试 |
| ③ 大纲生成 | 新建大纲（内联）+ 现有大纲列表 | AI 解析时选招标文件 |
| ④ 内容编辑 | 选定大纲的章节树概览 | 跳 `/outlines/:id` 编辑 |
| ⑤ 导出 | Word 文档列表 | 跳 Word 编辑器 |

### 关键设计点

1. **步骤导航条是主线但非强制**：可点任意步骤跳转，状态徽章显示当前进度。
2. **左侧常驻文件&大纲列表**：上下文锚点，解决"我在哪个标段、有哪些素材"的认知问题。可折叠（窄屏收起为图标）。
3. **空状态引导**：标段未关联文件时，①步骤显示"拖拽招标文件开始"。

## 5. 异步状态聚合

### 后端新增接口

```
GET /api/lots/:lotId/workbench_status/
```

返回该标段完整制作状态聚合：

```json
{
  "lot": { "id": 1, "name": "标段A", "status": "active" },
  "current_step": "file_parsing",
  "steps": {
    "tender_file": {
      "status": "done",
      "file_count": 2,
      "latest_file": { "id": 5, "name": "xxx.docx", "status": "parsed" }
    },
    "file_parsing": {
      "status": "doing",
      "parsing_files": [{ "id": 6, "name": "yyy.docx", "progress": 60 }]
    },
    "outline_generation": {
      "status": "pending",
      "outlines": [{ "id": 1, "name": "主大纲", "status": "generated" }],
      "tasks": []
    },
    "content_editing": { "status": "pending", "current_outline_id": null },
    "export": { "status": "pending", "documents": [] }
  }
}
```

### 状态推导规则（后端按优先级）

1. 有解析中文件 → `current_step = file_parsing`
2. 有生成中大纲任务 → `current_step = outline_generation`
3. 否则按最高完成步骤推导

### 前端轮询策略

| 场景 | 策略 |
|------|------|
| 工作台可见 + 有 doing 状态 | 每 3 秒轮询聚合接口 |
| 工作台可见 + 全部 done/pending | 停止轮询 |
| 离开工作台但任务进行 | 写入 localStorage（标段 ID + 任务摘要）；项目详情页标段卡片显示"进行中"徽章；回工作台恢复轮询 |
| 浏览器关闭/刷新 | 重新进入时聚合接口返回的 `current_step` 直接还原状态 |

### 进度展示

- 顶部步骤条：✓/⏳/✗ 状态
- 左侧文件列表：解析中文件显示进度条
- 失败：红色徽章 + 点击查看 error_message
- 任务完成：ElNotification 全局通知

## 6. 上传与解析整合

### 新流程（工作台 ①② 步）

**步骤 ① 招标文件**：
- 拖拽上传区 + 文件列表（当前标段的）
- 拖拽即传，`lot_id` 自动填充，`file_category` 默认 `tender_file`（可在文件项上切换附件/澄清）
- 上传完成自动切换主工作区到 ②（路由不变，后端自动触发解析）

**步骤 ② 文件解析**：
- 显示当前标段所有文件的解析进度
- 单个文件可展开看解析结果摘要（分块数、关键需求条数）
- 解析失败：内联显示错误 + 重试（不跳页面）
- "查看完整文件详情"作为次要链接保留 → `/tender/files/:fileId`

### 文件状态前端简化（后端不变）

| 内部状态 | 展示状态 |
|---------|---------|
| uploading | 上传中 |
| parse_pending, parsing, chunking, processing | 解析中（带进度） |
| parsed, chunked, requirement_extracted | 已就绪 |
| parse_failed | 解析失败 |

后端状态保持兼容，前端做映射。

## 7. 大纲生成与编辑衔接

### 步骤 ③ 大纲生成

- 主工作区上半：现有大纲列表（含版本、状态、章节统计）
- 主工作区下半：新建大纲内联操作区（不弹窗），三种方式：
  - **手动创建**：输入名称 → 直接进 ④
  - **预设模板**：选模板 → 直接进 ④
  - **AI 解析**：下拉选招标文件（**只显示当前标段已解析的文件**）→ 提交异步任务 → 列表行显示进度

### 步骤 ④ 内容编辑

- 主工作区显示选定大纲的章节树概览（标题 + 状态徽章）
- "进入编辑" → 跳 `/outlines/:outlineId`（保留现有编辑页，不重做）
- 左侧大纲列表点哪个大纲，④ 就预览哪个

### AI 生成进度

- 提交后大纲行显示 `generating` + 进度条
- 进度从 `workbench_status.outline_generation.tasks` 拿
- 完成自动 `set_current`（后端已有）
- 失败：红色徽章 + 错误 + 允许重新生成

## 8. 导出与概览升级

### ⑤ 导出步骤

- 显示当前标段关联的 Word 文档列表（BidDocument）
- "生成 Word"按钮 → 选定大纲 → 生成（已有逻辑）
- 跳 `/bid-documents/:documentId/word-editor`（保留现有全屏编辑器）

### 概览页升级为标段进度看板

- 标段卡片网格：每张卡显示标段名 + 当前步骤（① 招标文件 / ② 解析中 / ③ 大纲生成 / ④ 编辑 / ⑤ 导出）+ 卡住/失败提示
- 点卡片 → 跳该标段工作台
- 解决多标段并行时"谁到哪了"的全局感知问题

## 9. 全局导航收口

### 心智模型

```
工作台（个人任务总览）
  → 项目管理（项目列表）
      → 项目详情（概览看板 / 成员 / 标段列表）
          → 标段工作台（①文件→②解析→③大纲→④编辑→⑤导出）★ 主战场
              → 大纲详情 /outlines/:id（重交互编辑）
              → 文件详情 /tender/files/:id（次要排错）
              → Word 编辑器（全屏编辑）
```

业务人员从工作台 → 项目 → 标段工作台，一条线到底。所有制作动作都在标段工作台完成，独立路由页（大纲/文件/Word）都是从工作台跳出的"深加工"页面，不再是入口。

## 10. 兼容性处理

- 旧路由 `/outlines`（大纲列表空页面）：保留但重定向到 `/projects`，并提示"请从项目进入标段工作台"
- 旧路由 `/tender/files/:fileId`、`/outlines/:outlineId`、`/bid-documents/:id/word-editor`：**全部保留**，直接访问仍可用（深加工页不依赖工作台上下文）
- 移除菜单项「标书制作」后，已存书签的用户访问 `/outlines` 会被重定向，不会 404

## 11. 影响范围与不做的事

### 改动

- **前端**：新增标段工作台页面；项目详情页瘦身（移除文件 tab，概览升级）；移除菜单项「标书制作」；`/outlines` 重定向
- **后端**：新增 `GET /api/lots/:lotId/workbench_status/` 聚合接口
- **保留不重做**：大纲详情编辑页、文件详情页、Word 编辑器

### 明确不做（YAGNI）

- 不重写大纲章节编辑器（保留 `/outlines/:id`）
- 不重写文件详情页（保留 `/tender/files/:id`）
- 不引入 WebSocket（先用轮询解决可见性，后续可平滑替换）
- 不改变后端文件状态机（前端做展示映射）
- 不动工作流模板、知识库等无关模块
