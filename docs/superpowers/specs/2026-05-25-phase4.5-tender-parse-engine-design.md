> **状态：** 待评审

## 1. 概述

### 1.1 背景

Phase 4.1-4.4 已完成项目基础、流程模板、标段工作流、前端页面。招标文件解析是标书生成的核心前置环节，需要从原始文件提取结构化数据，支撑后续条款理解、响应矩阵生成、标书内容生成。

### 1.2 目标

- 建立完整的解析流水线：TenderFile → ParsedDocument → TenderChunk → TenderRequirement
- 保留完整证据链：页码、章节路径、原文偏移量
- 支持幂等重跑：版本化、哈希去重、状态可恢复
- 规则优先实现：规则分块 + 规则抽取，后续可叠加 LLM

### 1.3 核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 解析引擎 | 占位实现 | MinerU/Marker 部署复杂，先建框架后对接 |
| 向量嵌入 | 暂不实现 | 与 Phase 4.6 提示词管理共享配置，使用阿里百炼 text-embedding-v4 |
| 分块策略 | 三层混合 | section → clause → window，规则优先 |
| 条款抽取 | 规则优先 | Phase A 规则抽取，Phase B 叠加 LLM 校正 |
| 状态管理 | PipelineJob | 多阶段状态独立管理，不污染 TenderFile |

## 2. 架构设计

### 2.1 数据流

```
TenderFile
  ↓
PipelineJob（parse）→ ParsedDocument
                        ↓
PipelineJob（chunk）→ TenderChunk（父子结构）
                        ↓
PipelineJob（requirement_extract）→ TenderRequirement
```

### 2.2 模型层次

| 层次 | 模型 | 职责 |
|------|------|------|
| 任务层 | PipelineJob | 流水线状态管理、版本化 |
| 文档层 | ParsedDocument | Markdown 解析结果、质量指标 |
| 分块层 | TenderChunk | 语义分块、类型分类、证据链 |
| 条款层 | TenderRequirement | 结构化需求项、响应策略 |

### 2.3 MVP 范围

**P0（核心）：**
- PipelineJob 模型
- ParsedDocument 模型（FK 多版本）
- TenderChunk 模型（父子结构、content_hash）
- ParseService 占位实现
- ChunkService 规则实现
- Celery 任务串联

**P1（后续）：**
- TenderRequirement 模型
- RequirementExtractService 规则实现

**P2（后续 Phase）：**
- TenderComplianceItem 响应矩阵
- TenderTable 表格结构化
- LLM 辅助抽取
- 向量嵌入

```python
def activate_parsed_document(parsed_doc: ParsedDocument) -> None:
    """切换活跃版本（事务保护）。"""
    with transaction.atomic():
        ParsedDocument.objects.filter(
            tender_file=parsed_doc.tender_file
        ).update(is_active=False)
        parsed_doc.is_active = True
        parsed_doc.save(update_fields=["is_active", "updated_at"])
```

## 7. 分块策略设计

### 7.1 三层混合分块

```
一级（section）：按目录/标题切分
二级（clause）：按条款编号切分
三级（window）：按长度窗口兜底
```

### 7.2 章节识别模式

**匹配顺序：先匹配更具体的模式。**

| 优先级 | 模式 | 正则 | 示例 |
|--------|------|------|------|
| 1 | 层级编号（三级） | `^\d+\.\d+\.\d+` | 1.1.1、2.3.4 |
| 2 | 层级编号（二级） | `^\d+\.\d+` | 1.1、2.3 |
| 3 | 中文数字章节 | `第[一二三四五六七八九十]+章` | 第一章、第二章 |
| 4 | 中文数字节 | `第[一二三四五六七八九十]+节` | 第一节、第二节 |
| 5 | 中文数字条 | `第[一二三四五六七八九十]+条` | 第一条、第二条 |
| 6 | 括号中文 | `（[一二三四五六七八九十]+）` | （一）、（二） |
| 7 | 阿拉伯编号 | `^\d+\.` | 1.、2.、3. |

### 7.3 条款编号识别模式

**匹配顺序：先匹配更具体的模式。**

| 优先级 | 模式 | 正则 | 示例 |
|--------|------|------|------|
| 1 | 层级编号（多级） | `^\d+\.\d+(\.\d+)+` | 3.2.1、4.1.2.3 |
| 2 | 层级编号（二级） | `^\d+\.\d+` | 3.2、4.1 |
| 3 | 括号数字 | `（\d+）` | （1）、（2） |
| 4 | 字母编号 | `^[A-Za-z]\.` | A.、B.、a.、b. |

### 7.4 强制条款标记识别

**符号标记：**
- `★`、`※`、`●`

**注意：** `*` 符号容易与 Markdown 列表、脚注、强调混淆，不单独作为强制标记。只有当 `*` 后紧跟强制关键词时才识别：

```python
# * 后面紧跟强制关键词才识别
MANDATORY_STAR_PATTERN = r"\*[\s]*(必须|不得|应|废标|实质性要求)"
```

**关键词标记：**
```python

    "否则作废标处理", "废标",
    "否则视为", "视为放弃",
```

```python
class ParseService:
    """文档解析服务（占位实现）。"""

    VERSION = PARSER_VERSION

    def parse(self, tender_file: TenderFile) -> ParsedDocument:
        """解析招标文件，返回 ParsedDocument。

        当前为占位实现，生成 Mock 数据。
        后续对接 MinerU/Marker 时替换实现。
        """
        # 计算输入哈希（基于文件内容或 MinIO ETag）
        input_hash = self._compute_input_hash(tender_file)

        # 生成 Mock Markdown
        markdown = self._generate_mock_markdown(tender_file)

        # 计算 quality_metrics
        quality_metrics = self._compute_quality_metrics(markdown)
        page_count = self._count_pages(markdown)

        # 上传到 MinIO
        markdown_uri = self._upload_to_minio(markdown)

        # 计算输出哈希（基于 Markdown 内容）
        output_hash = self._compute_output_hash(markdown)

        # 切换活跃版本（事务保护）
        with transaction.atomic():
            ParsedDocument.objects.filter(
                tender_file=tender_file
            ).update(is_active=False)

            parsed_doc = ParsedDocument.objects.create(
                tender_file=tender_file,
                is_active=True,
                markdown_uri=markdown_uri,
                page_count=page_count,
                parse_engine="mock",
                parser_version=self.VERSION,
                parse_quality=ParseQuality.HIGH,
                quality_metrics=quality_metrics,
                input_hash=input_hash,
                output_hash=output_hash,
            )

        return parsed_doc

    def _compute_input_hash(self, tender_file: TenderFile) -> str:
        """计算输入哈希（基于文件内容）。"""
        # 方案一：使用 MinIO 对象 ETag
        # etag = storage_service.get_object_etag(tender_file.object_key)
        # return etag

        # 方案二：读取文件内容计算哈希
        from hashlib import sha256
        content = storage_service.get_object(tender_file.object_key)
        return sha256(content).hexdigest()

    def _compute_output_hash(self, markdown: str) -> str:
        """计算输出哈希（基于 Markdown 内容）。"""
        from hashlib import sha256
        return sha256(markdown.encode("utf-8")).hexdigest()
```

### 8.2 ChunkService（规则实现）

```python
class ChunkService:
    """语义分块服务（规则实现）。"""

    VERSION = CHUNKER_VERSION

    def chunk(self, parsed_doc: ParsedDocument) -> List[TenderChunk]:
        """对解析文档进行语义分块。

        三层混合策略：section → clause → window
        父子结构分批写入。
        """
        markdown = self._load_markdown(parsed_doc.markdown_uri)

        # 一级：章节分块
        section_chunks = self._split_sections(markdown, parsed_doc)

        # 先写入 section chunks，获取 ID
        TenderChunk.objects.bulk_create(
            section_chunks,
            ignore_conflicts=True,  # 处理唯一冲突
        )

        # 建立 section 映射（用于设置 parent_chunk）
        section_map = {}
        for chunk in TenderChunk.objects.filter(
            parsed_document=parsed_doc,
            chunk_level=ChunkLevel.SECTION,
        ):
            section_map[chunk.section_path] = chunk

        # 二级：条款分块
        clause_chunks = []
        for section in section_chunks:
            clauses = self._split_clauses(section)
            # 设置 parent_chunk
            for clause in clauses:
                if section.section_path in section_map:
                    clause.parent_chunk = section_map[section.section_path]
            clause_chunks.extend(clauses)

        # 写入 clause chunks
        TenderChunk.objects.bulk_create(
            clause_chunks,
            ignore_conflicts=True,
        )

        # 建立 clause 映射
        clause_map = {}
        for chunk in TenderChunk.objects.filter(
            parsed_document=parsed_doc,
            chunk_level=ChunkLevel.CLAUSE,
        ):
            clause_map[chunk.clause_no] = chunk

        # 三级：窗口兜底
        window_chunks = []
        for clause in clause_chunks:
            if clause.token_count > MAX_TOKENS:
                windows = self._split_windows(clause)
                # 设置 parent_chunk（优先 clause，其次 section）
                for window in windows:
                    if clause.clause_no in clause_map:
                        window.parent_chunk = clause_map[clause.clause_no]
                    elif clause.section_path in section_map:
                        window.parent_chunk = section_map[clause.section_path]
                window_chunks.extend(windows)

        # 写入 window chunks
        TenderChunk.objects.bulk_create(
            window_chunks,
            ignore_conflicts=True,
        )

        # 类型分类 + 特征提取（更新已写入的 chunks）
        all_chunks = TenderChunk.objects.filter(parsed_document=parsed_doc)
        for chunk in all_chunks:
            self._classify_chunk(chunk)
            self._extract_features(chunk)

        # 批量更新
        TenderChunk.objects.bulk_update(
            all_chunks,
            fields=[
                "chunk_type",
                "secondary_types",
                "classification_confidence",
                "matched_keywords",
                "is_mandatory",
                "has_deadline",
                "has_amount",
                "has_score",
                "has_penalty",
                "has_timeline",
            ],
        )

        return list(all_chunks)

    def _classify_chunk(self, chunk: TenderChunk) -> None:
        """分类分块类型。"""
        scores = {}
        for chunk_type, keywords in CHUNK_TYPE_KEYWORDS.items():
            score = sum(1 for kw in keywords if kw in chunk.content)
            scores[chunk_type] = score

        # 取最高分类型
        primary_type = max(scores, key=scores.get)
        if scores[primary_type] > 0:
            chunk.chunk_type = primary_type
            chunk.classification_confidence = scores[primary_type] / sum(scores.values())
        else:
            chunk.chunk_type = ChunkType.GENERAL
            chunk.classification_confidence = 0.0
```

```python
class RequirementExtractService:
    """条款抽取服务（规则实现）。"""

    VERSION = REQUIREMENT_EXTRACTOR_VERSION

    def extract(self, parsed_doc: ParsedDocument) -> List[TenderRequirement]:
        """从分块中抽取结构化需求项。"""
        chunks = TenderChunk.objects.filter(parsed_document=parsed_doc)

        requirements = []
        for chunk in chunks:
            if self._is_requirement_candidate(chunk):
                req = self._extract_requirement(chunk)
                if req:
                    requirements.append(req)

        # 计算 requirement_key 去重
        unique_reqs = self._deduplicate(requirements)

        # 批量写入（处理唯一冲突）
        TenderRequirement.objects.bulk_create(
            unique_reqs,
            ignore_conflicts=True,
        )

        return unique_reqs

    def _is_requirement_candidate(self, chunk: TenderChunk) -> bool:
        """判断是否为需求候选项。"""
        # 强制条款一定是需求
        if chunk.is_mandatory:
            return True

        # 特定类型一定是需求
        if chunk.chunk_type in [
            ChunkType.QUALIFICATION,
            ChunkType.SCORING,
            ChunkType.TECH_REQ,
        ]:
            return True

        return False

    def _extract_requirement(self, chunk: TenderChunk) -> TenderRequirement:
        """从分块抽取需求项。"""
        req = TenderRequirement(
            tender_file=chunk.parsed_document.tender_file,
            parsed_document=chunk.parsed_document,
            source_chunk=chunk,
            requirement_type=chunk.chunk_type,
            title=chunk.section_title,
            content=chunk.content,
            mandatory_level=self._determine_mandatory_level(chunk),
            risk_level=self._determine_risk_level(chunk),
            response_needed=True,
            evidence_needed=self._needs_evidence(chunk),
            evidence_types=self._get_evidence_types(chunk),
            response_strategy=self._determine_response_strategy(chunk),
            owner_role=self._determine_owner_role(chunk),
            source_page_start=chunk.page_start,
            source_page_end=chunk.page_end,
            source_section_path=chunk.section_path,
            extraction_method=ExtractionMethod.RULE,
        )

        req.requirement_key = self._compute_key(req)

        return req
```

```python
        tender_file=tender_file,
```

### 12.3 实现注意事项

**关键工程细节，必须遵守：**

1. **input_hash 必须基于文件内容或对象 ETag**
   - 不能仅基于 `object_key`（只是路径，不代表内容）
   - 推荐：`sha256(file_bytes)` 或 MinIO ETag

2. **output_hash 必须基于解析结果内容**
   - 不能仅基于 URI（只是路径，不代表内容）
   - 推荐：`sha256(markdown_content)`

3. **ParsedDocument 切换 is_active 必须使用事务**
   - 保证同一 TenderFile 只有一个 active 版本
   - 使用 `transaction.atomic()` 包裹

4. **TenderChunk 父子结构必须分批写入**
   - 先写 section chunks，获取 ID
   - 再写 clause chunks，设置 parent_chunk
   - 最后写 window chunks
   - 不能一次性 `bulk_create` 所有层级

5. **bulk_create 必须处理唯一冲突**
   - 使用 `ignore_conflicts=True` 或 `update_conflicts`
   - 避免重跑时重复插入报错

6. **强制条款符号 `*` 需要谨慎识别**
   - `*` 容易与 Markdown 列表、脚注、强调混淆
   - 只有当 `*` 后紧跟强制关键词时才识别

7. **正则匹配优先匹配更具体的模式**
   - `1.1.1` 应先于 `1.1` 匹配
   - `1.1` 应先于 `1.` 匹配

8. **Celery 异常处理要避免未定义变量**
   - `job` 变量先初始化为 `None`
   - `except` 块中检查 `if job:` 再调用 `_mark_job_failed`
