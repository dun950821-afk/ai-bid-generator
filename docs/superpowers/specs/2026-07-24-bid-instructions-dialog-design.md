# 标书制作说明对话框 - 设计文档

## 背景与目标

`/projects` 项目列表页当前只有"新建项目"一个操作入口，新用户进入后无法直观了解整个标书制作的链路：上传招标文件 → AI 解析（含 4 个子阶段）→ 大纲生成 → 内容编辑（生成准备/矩阵/批量生成/废标检查/一致性审计）→ 导出 Word。

本设计在"新建项目"按钮旁新增一个"标书制作说明"按钮，点击弹出对话框，以分步卡片形式详细说明流程，并提示流程模板等功能暂未启用、可任选。

## 涉及范围

- 仅前端改动
- 新增组件：`frontend/src/views/projects/components/BidInstructionsDialog.vue`
- 修改文件：`frontend/src/views/projects/ProjectListView.vue`
- 无后端、无数据库、无 API 变更
- 无新增依赖

## 步骤文案（详细版，定稿）

### ① 招标文件上传

把招标文件（PDF / Word）传到对应标段下。

- 在标段工作台第 1 步点击上传，支持多文件
- 上传后会自动进入"文件解析"阶段，无需手动触发
- 若同一标段有多份招标文件（澄清、补遗），全部上传即可

### ② AI 解析文件（核心，最耗时）

系统会自动对每份招标文件依次执行 4 个子阶段，每完成一个会实时刷新状态：

1. **文档解析**：把 PDF/Word 转为可读文本与结构（约 0–35%）
2. **语义分块**：把长文档切成可检索的语义段落（35–65%）
3. **条款抽取**：自动识别 6 类关键条款——评分项、废标项、资质要求、商务要求、技术要求、投标文件要求（65–95%）
4. **向量嵌入**：把分块写入向量库，供后续生成时检索引用（95–100%）

- 整个过程通常需要 1–3 分钟，取决于文件大小
- 任一子阶段失败可点「重试」，无需重新上传
- 解析进度条会实时显示当前阶段与百分比

### ③ 大纲生成

基于解析出的条款，生成投标文件大纲骨架。

- 进入标段工作台第 3 步，选择「AI 解析大纲」模式
- 选择已解析的招标文件，点击「创建大纲」
- 系统调用 AI 生成章节目录（可后续手动增删、调整）
- 一个标段可创建多个版本大纲，需点「设为当前」指定主版本

### ④ 内容编辑（最核心写作环节）

进入大纲详情页，逐章生成并打磨正文。

- **生成准备**（弹窗内完成）：创建材料包、关联知识库、触发「全局事实变量」抽取——这一步决定 AI 生成内容的准确性，**必须先做**
- **生成内容责任矩阵**：为每个章节定义写作边界与生成策略
- **批量生成 / 单章生成**：AI 按矩阵生成正文，可单章「AI 生成」或一键「批量生成」
- **废标检查**：扫描正文是否触犯废标条款（投标方必做）
- **一致性审计**：检查全文术语、数据、口径一致性
- 全部章节就绪后点「生成 Word」产出投标文件

### ⑤ 导出

在标段工作台第 5 步查看与下载投标文件。

- 点击「打开编辑器」用 ONLYOFFICE 在线编辑/复核
- 满意后下载最终 Word 文档

### 底部提示文案

> ⚠️ 提示：当前「流程模板」「企业材料」「知识库」等功能尚在完善，创建项目时**流程模板可任选一个内置模板**，不影响上述标书制作流程。

## 组件设计

### BidInstructionsDialog.vue

- 位置：`frontend/src/views/projects/components/BidInstructionsDialog.vue`
- 类型：SFC，`<script setup lang="ts">`
- Props:
  ```ts
  defineProps<{ modelValue: boolean }>()
  ```
- Emits:
  ```ts
  defineEmits<{ 'update:modelValue': [value: boolean] }>()
  ```
- 内部数据：步骤文案作为静态常量数组 `STEPS`，每项结构：
  ```ts
  interface Step {
    no: number
    title: string
    summary: string
    bullets?: string[]        // 普通圆点列表
    ordered?: string[]        // 编号列表（仅第 2 步用）
  }
  ```
- 无 API 调用，无生命周期副作用

### ProjectListView.vue 修改

新增导入：
```ts
import { QuestionFilled } from '@element-plus/icons-vue'
import BidInstructionsDialog from './components/BidInstructionsDialog.vue'
```

新增 ref：
```ts
const showInstructions = ref(false)
```

`toolbar-right` 模板修改：
```html
<div class="toolbar-right">
  <el-button @click="showInstructions = true">
```

不改动其他逻辑（搜索、筛选、卡片、分页、新建项目弹窗等）。

## 视觉细节

- 步骤卡：`background: var(--el-bg-color-page)`、`border: 1px solid var(--el-border-color-lighter)`、`border-radius: 8px`、`padding: 16px`
- 步骤序号徽章：圆形 24×24，主色填充，白色数字，`font-weight: 600`
- 子步骤圆点：`•` 字符，颜色 `var(--el-text-color-secondary)`，与文字间距 8px
- 编号列表（第 2 步）：使用 `<ol>` 默认编号，加粗子阶段名（`<strong>`）
- hint alert：`type="warning"`，`show-icon`，`:closable="false"`
- 对话框 body：`max-height: 70vh; overflow-y: auto`

## 验证

由于仅前端 UI 改动，验证步骤：

1. `cd frontend && npm run build` 成功
2. 本地 `npm run dev` 后访问 `/projects`，看到"标书制作说明"按钮位于"新建项目"按钮左侧
3. 点击按钮弹出对话框，5 个步骤卡完整展示，第 2 步含 4 个编号子阶段
4. 底部 hint 文案显示为 warning alert
5. 点击"我知道了"或右上角 ✕ 关闭对话框
6. 不影响"新建项目"等其他原有功能
7. 浏览器控制台无错误

## 不做

- 不做 localStorage 记住"已读"——按需点开即可，避免增加状态管理复杂度
- 不做步骤间跳转链接（如点击"第 2 步"跳到对应标段）——避免依赖具体项目上下文
- 不做后端 API——文案静态、维护成本低
- 不做 i18n——当前项目仅中文
