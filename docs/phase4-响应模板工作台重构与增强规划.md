# Phase 4 规划: 响应模板工作台重构 + 4 项增强

> 背景: 用户反馈当前入口不合理 —— 文件详情页"识别响应模板"按钮点一次新建一个模板,
> 无幂等; 创建后页面无内容展示; 状态流转不清晰。需要完全重新设计入口与工作台。

## 一、现状问题(BOSS 反馈)

1. 入口无幂等: 每次点击都 POST 新建模板, 重复创建
2. 创建后无内容: 识别中页面空白, 用户不知道发生了什么
3. 状态流转不清晰: 没有步骤概念, 不知道当前处于哪个环节
4. 没有统一工作台: 响应模板散落在列表里, 与项目/招标文件脱节

## 二、目标: 响应模板 = "招标文件 → 响应文件"的工作台

一个招标文件对应**一个**响应模板(幂等), 状态机:

```
  pending(待识别) → analyzing(识别中) → analyzed(待确认)
      → confirmed(已确认) → generating(生成中) → generated(已生成)
            ↘ failed(失败, 可重试)
```

流转动作:
- 创建(幂等): 同 source_file 已有模板 → 返回已有, 不重复创建
- re-analyze: 重新识别(重置为 pending, 删旧块)
- confirm: analyzed → confirmed
- generate: confirmed → generating → generated
- 已生成后可再次 generate(重新生成, 覆盖产物)

## 三、入口重构(三处)

1. **招标文件详情页**
   - "识别响应模板"按钮 → 改为调用幂等创建接口(已有则返回已有模板)后
     跳转工作台; 若已有模板, 按钮文案变更为"进入响应模板"(显示状态徽标)
   - 文件详情页新增"响应文件"状态卡片: 模板状态/置信度/产物数量 + 进入按钮
2. **标段工作台(LotWorkbenchView)**
   - 新增"响应文件"卡片: 该标段响应模板状态 + 一键进入
3. **响应模板工作台(详情页重构, 见下)**

## 四、工作台页面重构(步骤条驱动)

顶部 Stepper 五步:
  ① 招标文件 → ② 识别响应格式 → ③ 确认填充位置 → ④ 生成响应文件 → ⑤ 下载/校对

- 状态自动映射步骤, 当前步骤高亮
- 识别中: 显示进度(已识别附件 x/N, 轮询 3s)
- 待确认: 块列表(现有, 按附件分组/类型筛选/批量确认)
- 已确认: 生成按钮 + 提示待复核项
- 已生成: 产物卡片(主文件/密封文件, 下载 + ONLYOFFICE 校对)
- 失败: 错误信息 + 重试按钮(re-analyze / 重新生成)

## 五、4 项增强实施方案

### 增强 1: Content Control 编译定位(v2 定位)

现状: 文本锚点定位(有歧义风险)。
方案: 识别完成后生成 compiled 模板:
- 对每个块在原始 docx 中定位锚点段落/cell, 注入 <w:sdt> 控件
  (Tag = bid.<type>:<key>, 复用 template_variable_registry 协议)
- 存储: template.compiled_file_key(模型字段已存在)
- 填充: filler 优先扫描 bid.* 控件精确定位, 找不到回退文本锚点
- 好处: 定位零歧义, 锚点唯一性由控件保证
- 工作量: 大(需处理段落/表格 cell/行三种注入)

### 增强 2: 人员库 + AI 推荐 + REPEAT_BLOCK 字段填充

- 新建 ProjectMember 模型(企业人员库):
  name/role(角色)/title(职称)/certificates(证书)/experience_years(年限)/
  projects(项目经历)/material(社保证明材料 FK)
- 企业资料中心新增"项目人员"页(列表/新增/编辑)
- filler REPEAT_BLOCK 增强: 复制后按块内锚点字段
  (姓名/角色/工作年限/证书)匹配人员库填充; AI 推荐:
  根据附件6 人员资格要求文本筛选匹配人员, 前端确认后填充
- v1 简化: 复制块 + 块内字段定位填充(姓名/年限等)+ 前端人员选择

### 增强 3: 双栏预览(低成本版)

- 工作台"待确认"步骤提供"预览"开关:
  左栏 = 解析后的附件内容文本(markdown 渲染, 按附件导航)
  右栏 = 当前附件块列表
- 不引入 ONLYOFFICE 嵌入(成本高), 先做 markdown 双栏
- 后续可升级: 点击块 → 定位到左栏对应文本高亮

### 增强 4: 报价对接(轻量版)

- quotation app 为空壳, 不依赖它
- PRICE 块支持前端在线编辑: 展开显示报价字段(高危/中危/低危单价),
  用户填写保存到 fill_payload; 生成时填充到文档
- filler PRICE 处理: 有 fill_payload.price → 填充空位; 无 → 保留人工
- 前端: PRICE 块行内编辑表单

## 六、实施步骤

1. 后端: 幂等创建 + re-analyze action + 状态机完善(任务)

3. 前端: 标段工作台响应文件卡片
4. 前端: 工作台步骤条重构 + 识别进度
5. 增强 4: PRICE 在线编辑(快)
6. 增强 3: 双栏预览(markdown)
7. 增强 2: 人员库(模型/API/前端/填充)
8. 增强 1: Content Control 编译定位(最大, 最后)
9. 测试 + 端到端 + 部署 + 提交

- 单测 + 常熟文件端到端
